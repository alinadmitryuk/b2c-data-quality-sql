# B2C Data Quality & Migration Monitoring

Пет-проект по SQL, ориентированный на стажёрскую позицию в data / B2C data operations.

## Цель

Смоделировать работу с B2C-данными в сценарии, где нужно:

- проверять качество данных;
- анализировать бизнес-показатели;
- контролировать миграцию с legacy-системы в новую таблицу;
- искать аномалии и потери данных;
- анализировать результаты A/B-теста.

## Стек

- PostgreSQL
- SQL
- CSV
- Excel (опционально для визуализации результатов)
- GitHub

## Данные

### users_legacy

- `user_id` — идентификатор пользователя
- `name` — имя
- `email` — email
- `registration_date` — дата регистрации
- `country` — страна
- `age` — возраст

### orders_legacy

- `order_id` — идентификатор заказа
- `user_id` — пользователь
- `order_date` — дата заказа
- `amount` — сумма заказа
- `status` — статус заказа

### experiments

- `user_id` — пользователь
- `group_name` — `control` или `test`
- `converted` — 0/1

## Намеренно внесённые проблемы качества данных

В датасетах есть искусственно добавленные ошибки, чтобы можно было показать полноценную data-quality проверку:

- пропущенные email;
- дублирующиеся email;
- некорректный возраст;
- пропущенная страна;
- отрицательная сумма заказа;
- пропущенная сумма;
- заказ с несуществующим пользователем;
- пропущенный статус;
- дублирующийся `order_id`.

## Что демонстрирует проект

### 1. Data Quality

Проверяются:

- completeness — пропуски;
- uniqueness — дубли;
- validity — допустимость значений;
- referential integrity — существование связанных пользователей;
- consistency — совпадение данных между версиями таблиц.

### 2. SQL

Использованы:

`SELECT`, `WHERE`, `IS NULL`, `BETWEEN`, `IN`, `CASE`, `COALESCE`, `NULLIF`, агрегатные функции, `GROUP BY`, `HAVING`, `INNER JOIN`, `LEFT JOIN`, подзапросы, `CTE`.

### 3. Migration validation

После копирования данных в `orders_new` сравниваются:

- количество строк;
- общая выручка;
- отсутствующие записи;
- дубли;
- изменения значений полей.

### 4. A/B testing

Считаются:

- размер групп;
- количество конверсий;
- conversion rate;
- absolute uplift;
- relative uplift.

Важно: uplift сам по себе не доказывает статистическую значимость результата. Для полноценного A/B-анализа отдельно нужны статистический тест и проверка достаточности выборки.

## Как запустить

1. Создать БД PostgreSQL.
2. Выполнить `01_schema.sql`.
3. Загрузить три CSV в соответствующие таблицы.
4. Последовательно выполнить `02_data_quality.sql`, `03_analysis.sql`, `04_migration.sql`, `05_ab_test.sql`.
